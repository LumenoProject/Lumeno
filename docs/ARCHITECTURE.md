# Lumeno 架构与协议不变量

## 运行结构

浏览器只连接同源 Caddy。Caddy 终止 TLS 并反向代理到单个 Rust 进程；Rust 同时提供 JSON API 和已构建的 Vue 静态文件。PostgreSQL 是协议事实的最终来源。

```text
Browser / installed PWA
  ├─ Vue 3 + Pinia + IndexedDB outbox
  └─ Service Worker (precache)
             │ HTTPS / same origin
          Caddy 2
             │ private HTTP
       Axum BFF + protocol service
          ├─ external OIDC provider
          └─ PostgreSQL 18
```

OIDC client secret、通知配置加密密钥和数据库凭据只存在于服务端环境。每用户 Bark 地址、Bark 内容加密密钥以及 Webhook Bearer Token 使用 AES-256-GCM 加密入库，密文以用户 ID 与渠道类型作为附加认证数据。浏览器获得的会话标识位于 `HttpOnly; SameSite=Lax` cookie；可读的 CSRF cookie 必须与请求头以及服务端哈希同时匹配。

OIDC 登录使用 Authorization Code + PKCE、一次性 state 与 nonce。ID Token 中的 `sid` 会与本地会话关联；后通道登出只接受提供方 JWKS 验签通过、issuer/audience 匹配、15 分钟内有效且包含标准登出事件的 Logout Token，并以 `jti` 防止重放。按 `sid` 撤销单次提供方会话；Token 不含 `sid` 时才按 `sub` 撤销该账号的全部本地会话。

## CTDP 状态机

### 预约链

```text
本地预提交（10 秒内可撤销）──窗口结束──> pending ──预约时间到达──> 90 秒启动窗口 ──按发生时间及时启动──> fulfilled (+辅助连续)
                                  │
                                  └─绝对截止时间到达─> awaiting_judgment
                                                         ├─failure─> failed (辅助连续归零)
                                                         ├─allow───> allowed (+辅助连续，永久先例)
                                                         └─5 分钟未确认─> failed (辅助连续归零，服务端自动审计)
```

点击开始或预约后，客户端先持久化一个以原始点击时间为锚点的本地预提交，并立即显示全屏倒计时。前 10 秒允许无后果撤销；窗口结束后使用稳定 UUID 幂等地创建服务端事实，计时不会因此顺延 10 秒。预约提交需要联网，断网时会保持全屏等待，并在恢复联网后按原始点击时间提交。

预约倒计时和随后的 90 秒启动窗口都由服务端绝对时间定义，浏览器仅据此显示状态。启动窗口截止后有 5 分钟确认窗口；失败或永久允许判定完成后预约立即成为终态，不再阻止开始或再次预约。确认窗口同样由服务端绝对时间控制，超时无需网页在线即可自动失败并释放状态。离线回放使用事实发生时间，而不是同步抵达时间。发生时间只接受“未来不超过 5 分钟、过去不超过 7 天”的窗口。

用户可在预约倒计时或启动窗口中主动终止预约。终止不会静默撤销承诺，而是立即进入同一个 5 分钟“失败或永久允许”判定窗口，并取消尚未投递的预约启动通知。

### 主链专注

```text
running ──绝对截止时间到达──> completion_ready ──完成──> succeeded
   │                                  (+主连续)
   └─中断/提前结束─> awaiting_judgment
                       ├─failure──────────────> failed (主连续归零)
                       ├─allow early_end──────> succeeded
                       └─allow interrupt──────> running/completion_ready
```

没有 pause 状态。倒计时由 `completion_available_at` 绝对时间推导，刷新、休眠、切换页面或断网都不改变截止时间。

### 任务群

启动时递归展开当前树中的叶子任务，形成不可变的有序运行快照。只允许启动快照中的下一个未完成叶子。任务群时限失败只清零任务群链；正在执行的叶子会与失败的运行周期解绑，仍按自己的主链承诺完成。允许超时会建立 `group_deadline` 永久先例，并仅对当前周期解除时限。

核心承诺字段变化不原地覆盖：旧修订归档，新修订获得新的 ID、连续记录从零开始，先例继续永久保存在旧修订上。活动预约、专注或任务群运行存在时禁止核心变更和归档。

## RSIP 状态机

RSIP 将稳定的国策身份、不可改写修订、当天成功试行和树中部署拆成独立事实。未产生试行或部署历史的当前修订可原地纠正；一旦产生历史，后续编辑创建带 `previous_revision_id` 的新修订，既有试行和部署继续引用旧修订。

```text
国策库 ──当天当前修订试行成功──> 可部署试行 ──消费试行──> 活动部署
   ▲                                                   │
   └──────────────────定义保留，未来重新试行─────────────┘ 失效
```

试行和部署日期都由用户 IANA 时区在服务端计算。部署事务锁定试行与国策，要求试行属于当天、当前修订且尚未消费；数据库唯一索引再保证每位用户每个本地日期最多新增一条国策部署、同一国策最多一个活动部署。所有 RSIP 写操作使用每用户事务级 advisory lock 串行化。关系外键同时包含 `user_id`，即使绕过 API 也不能建立跨用户的国策、修订、父子或组成员引用。

普通活动部署失效时，一个事务会乐观锁定版本、递归选择自身与全部依赖后代、累计每个国策本轮实际生效秒数、熄灭完整子树并写入事件。查询国策库时，累计秒数会再加上当前活动轮尚未结算的时长；界面只把完整 86400 秒显示为一个累计存活日，不将其解释为习惯评分。

### 国策组

组定义满足 `1 ≤ minimum_active_members ≤ target_member_count ≤ 50`。树中的组节点通过独立成员关系连接国策部署；成员不能同时作为普通下游父节点。活动成员达到最低点亮数后，组可承载下游：

- 成员失效后仍满足门槛，只熄灭该成员；
- 跌破门槛时保留组和其他成员，熄灭该组全部下游，组状态由 `group_ever_effective` 与当前活动成员数派生为“降级”；
- 后续补足成员会重新点亮组，但已经熄灭的下游不复活；
- 普通上游或组节点自身失效时，递归边同时包含父子关系和组成员关系，因此组、成员与下游全部熄灭。

失败预览最多返回 1000 个节点摘要并同时给出实际总数，避免把巨型子树一次性载入应用进程；事务中的数据库递归更新始终覆盖完整影响集合。概览、定义和成员读取均有固定上限，历史使用最大 100 条的游标分页。

当前迁移只定义空数据库初始化结果，不包含旧 `rsip_nodes` 表的数据升级或回填。

## 离线与幂等

10 秒预提交状态先写入 IndexedDB，刷新页面不会重新获得或丢失撤销窗口。离线专注在窗口结束后写入本地活动状态与 outbox，再更新 UI；start、complete、judgment 操作按创建时间顺序回放。每个操作有稳定 UUID 幂等键，开始会话与预约还使用同一个 UUID 作为服务端主键。永久 4xx 错误不会被静默删除，因而不会为了“同步成功”而丢失协议事实。

outbox 硬上限 1000 项。每位用户最多配置一个 Bark 或 Webhook 渠道；预约、专注与任务群的绝对截止时间会在相应事务中写入通知作业，后端服务器独立投递，不依赖浏览器会话。通知作业每批领取 50 个、最多重试 8 次并指数退避，终态作业保留 30 天。

## 并发和容量

- COMMITMENT RECORD 直接按当前用户的不可变协议事件汇总终态：只有专注或任务群真正完成才计入完成次数；预约兑现只更新预约连续与历史事件，不重复计为完成。相应失败和预约确认超时仍计为失守；非终态事件忽略，因此归档与修订不会改写累计次数。`(user_id,event_type)` 索引使汇总无需扫描其他用户或无关事件类型。
- 归档契约按用户隔离，并按归档时间倒序读取最近 1000 条；归档部分索引同时覆盖过滤与排序，避免历史增长后进行无界全量排序。
- PostgreSQL partial unique index 保证每位用户最多一个活动专注、每条链最多一个待决预约、每个任务群最多一个活动周期。
- 所有状态判定使用事务、行锁和版本号；同一用户的契约树结构修改与 RSIP 树修改分别使用事务级 advisory lock 串行化，封闭跨设备创建/归档竞态；协议事件的 `(user_id, idempotency_key)` 唯一。
- 到期协调每类每轮最多处理 1000 行，并使用针对状态的 partial index。
- 历史 API 使用有界页大小；审计表可以长期增长，但不会一次性加载到进程内存。
- 通知网络请求不持有数据库事务，禁用重定向并限制连接/总超时；配置和每次投递都要求目标的精确 HTTPS origin 已由部署者加入最多 32 项的 `NOTIFICATION_ENDPOINT_ALLOWLIST`，未配置或未命中时默认拒绝。白名单不包含通知路径或 Bark 设备密钥。OIDC token exchange 同样不持有事务。
